# MVP 验收与归档清单

日期：2026-10-18。范围：十单元、64 关、本地优先编程平台。云端账号、在线分享、真实 AI 服务仍不纳入本批。

此前的工程收尾通过 766 项单测、完整 198 项三视口浏览器回归、全课程机器汇总与生产入口加载检查；首页 JS 解码量约减少 80.2%，编辑器按需加载真实引擎。对应结果和边界见执行记录第 13–14 节。

随后完成用户反馈的 12 项课程体验修正：最终 772 项单测及格式/静态/类型/构建、针对性 18 项三视口交互回归、冻结基线及生产 v8 断网续玩/中文配音缓存均通过。该批没有重新执行之前完整的 198 项或全 64 课真实舞台整批；第 6 课新地图在三视口单独通关检查，全课程程序判定随单元测试重新执行。详见 [本轮修改与验收记录](lesson-experience-fixes-20261018.md)。

接下来优先安排下面的真实设备和儿童试玩，再做弱网/长时与发行审核。此前 `daf260f` 已按用户要求推送；本轮 12 项体验修正尚未提交、推送或部署。此前 CI 仅记录到配置修改，推送后的云端执行状态未在本轮查询，不能将本地通过等同于可正式发行。

## 1 当前执行顺序

1. 编辑器初始化稳定性：作品读取门禁、读取失败/超时重试、旧请求隔离、积木异步恢复与舞台重试。故障注入与回归结果按实际记录写入 [执行记录](p1-execution-log.md)。
2. 重跑现有课程、保存、几何与浏览器回归。测试程序预置或故障注入不等同于儿童手动操作。原始失败记录不因重跑通过而删除。
3. 真实设备与儿童试玩，按下面的表格记录，修改规则必须独立登记，不能为了过关降低原目标。
4. 基于实测的编辑器性能优化，而不是只提高构建包体告警阈值。
5. 整理发行素材与可回退版本，在用户明确授权后再提交、推送或部署。

## 2 需要人工完成的验收

设备条件更新（2026-10-18）：用户目前暂时只有电脑，型号、系统和浏览器尚未记录。先进行电脑端人工体验，不要求现在添置平板；平板触控继续标记“待验收”，不以鼠标或 WebKit 模拟替代，也不因此阻塞本地 MVP 的内部试用。

电脑端首轮顺序：第 1–6 关 → 路线转弯与循环 → 分类/图表 → 保存后刷新与续开。手动搭建程序，重点记录目标是否易懂、参数是否误触拖动、移动是否对齐格心、错误后修正重跑是否正常、代码与进度是否保留；随后再做 30 分钟连续使用。儿童试玩与完整读屏仍独立登记，不能因为成人电脑体验通过而一并勾选。

| 项目       | 方法                                                                               | 通过条件与证据                                                                                     |
| ---------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 真实平板   | 记录型号、系统、浏览器；手指拖动积木、修改循环次数、取消参数、舞台操作、横竖屏切换 | 不误拖、不丢代码，操作区域可见。记录截图、失败步骤及能否恢复；模拟 WebKit 不代替此项               |
| 初学者组   | 选第 1、2、3、6 关，观察首次进入、顺序连接与重复                                   | 记录耗时、首次成功、提示次数、儿童自己的解释；没有预置参考程序，不以成人代操作计通过               |
| 已有基础组 | 选第 7、25、28 关，观察碰撞、路径和循环组合                                        | 记录预判与实际结果、典型错误、修正方式和无提示迁移；同一结构换数值或场景后再次验证                 |
| 进阶组     | 按已有基础选择第 40、48、56 或 64 关                                               | 检查图表、规律、判断与综合目标是否可理解。不能要求零基础儿童直接完成全部后段关卡                   |
| 持续使用   | 在适合该学习者的任务组中持续使用 30 分钟                                           | 观察反复运行、停止、切关、复制、保存、重载、发热与卡顿。记录数据是否仍一致，不把短测试当成长时通过 |
| 辅助技术   | 键盘完整完成进课、参数、提示、关闭弹窗与返回；另做实际读屏检查                     | 焦点可见且返回合理，错误可理解，不仅用颜色区分状态；局部参数键盘测试不代表全站已验收               |

统一记录字段：日期 / 设备与浏览器 / 学习者基础（使用匿名编号，不记录儿童身份）/ 关卡 / 是否独立完成 / 用时 / 最高提示级 / 错误步骤 / 是否恢复 / 下一次修改建议。

## 3 性能专项

- 保存当前构建包体作为基准，分别记录首次首页、首次进入编辑器、缓存后的再次进入。Scratch / Pixi 已独立分包但依赖仍较大；包体本身不等同于实际加载时间。
- 在真实平板和受限网络下测量“可见 → 可编辑 → 可运行”，以及长时内存和帧率；冷启动与热缓存分开报告。
- 优先检查首页是否提前加载编辑器依赖、是否存在重复初始化/未释放资源、纹理解码、缓存和错误反馈，再选择分包或按需加载方案。
- 优化后复验合法程序、碰撞格心、素材解析、保存/重载和断网续玩，不通过改超时或降低任务要求来冒充优化。

本机生产入口检查与三次临时配置测量使用 `pnpm test:performance:entry`，结果为 `artifacts/performance/entry-after.json`；优化前记录为 `entry-before.json`。检查重点是首页/课程页不加载 Scratch/Pixi，而编辑器确实加载两者。该命令不限制 CPU/网络，记录的时间含自动化开销，不代替上面的真机、弱网和长时专项。

## 4 Git 与发行归档

当前工作区有多批未提交修改。先分类检查，不执行整仓库盲目暂存，不删除已有作品、参考资料或素材母版。

2026-10-18 只读盘点时，未跟踪参考原件为 84 个、约 97 MiB，验收证据约 132 MiB（后续测试仍会增加）。这些文件与正式运行资源不是同一类，不能直接整仓库公开上传。原始 WebKit 和路线复位失败追踪分别保存在 `artifacts/status-audit-20261018/` 及其 `workspace-reset-regression/` 子目录，重跑不删除原件。

| 分类                           | 处理                                                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 源码、正式资源、配置与必要测试 | 按功能批次检查差异和依赖完整性，准备可回退提交                                                                 |
| 冻结基线与课程夹具             | 保留原审计基线，不重新采集来掩盖差异                                                                           |
| 测试 JSON / 截图 / trace       | 保留验收所需证据；体积较大或含环境信息的诊断记录需单独检查是否进入 Git                                         |
| 参考资料与素材母版             | 保留本地原件，确认体积与发行边界，不能误删或未经核对全部公开上传                                               |
| 素材来源与发行状态             | 核对 [素材台账](baselines/story-ip-assets.json) 与 [来源说明](asset-provenance.md)；原型审查不等于发行审核完成 |

获得提交授权后，再逐批提交；推送与部署按用户授权执行。最后在干净工作副本中使用锁文件安装，运行质量检查、课程基线、完整浏览器测试与生产离线检查；失败保留追踪和未完成项，不宣称 CI 已通过。

## 5 完成口径

“自动化通过”“真实设备通过”“儿童教学验收通过”“可正式发行”是四种不同结论。当前初始化加固不代表原始 WebKit 间歇性故障的唯一底层原因已经确定；需要重复进入与长时真机记录继续验证。
