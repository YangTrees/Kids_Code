# 课程难度审核与修订 · 2026-10-14

审核范围：现有 64 关的教学目标、积木连接、运行判定、地图初始位置及前后衔接。
稳定保留全部 taskId、单元入口和已有完成记录。下面的顺序对应当前课程页。

## 难度原则

- 入门 → 练习 → 组合 → 进阶 → 综合，按概念、状态管理、嵌套和验收责任划分，不能只增加循环次数。
- 单元可独立进入，因此新主题允许热身。热身后应增加组合关系或测试责任，避免只改标题重复同一程序。
- 同一次运行中测试不同数据、边界值和真假条件；不能只检查“存在某种积木”或“运行结束”。
- 随机抽样允许重复结果，正确程序不依赖运气；要求实际输出与每个抽样匹配。
- 课程提示与地图要一致：新建宝箱关的角色、宝箱同一行，相距 3 个 40px 格子。

## 一并修复的课程基础问题

- 条件连接检查递归检查循环内部，嵌套的合法判断不再被遗漏。
- 判断分支内的“游戏成功”终止运行时，补齐已经执行的外层判断/循环证据。
- 对明确指定的回答核对完整文本，避免“未达标”因包含“达标”而被误认为正确。
- 重复关卡检查动作确实在循环内，指定动作必须真的执行足够次数。
- 显示五级难度标签，不用积木数量充当难度。

## 已有作品与验收

已有完成记录和程序不会强制重写。新版地图用课程页的“新建本关 · 保留原作品”入口创建；
已有保存的地图仍可继续编辑。特别是旧的竖直 path_repeat 地图，不应套用新版台阶解法。

自动检查包括全部 64 个项目的 schema、路线可达性，以及升级关卡从序列化积木经编译器到
真实 RuntimeSession 的参考解法。固定路径还验证八格台阶的完整路线。

自动测试不能代替儿童试用。后续应记录每关完成时长、尝试次数、提示次数和卡住的位置；
用这些数据调整提示力度、单元热身和综合关长度，避免单纯继续增加积木数量。
