## 2 角色身份锁定

### 团团：探索与尝试

- 7 岁左右的小男孩，黑灰色蓬松短发，圆润脸型与淡红脸颊。
- 橙色长袖上衣、蓝色牛仔背带裤和卷裤脚、棕色背包、棕白鞋；保持角色板中的关键颜色关系。
- 友好、好奇、会尝试也会犯错。动作服务于当前目标，如观察、指向、尝试和庆祝，不添加无关装备。
- 主舞台版本优先正面与朝右；头像版本优先好奇、指向、开心。全身图与头像必须是同一角色而不是两个近似人物。
- 不得变成当前项目同名熊猫，不改为女孩、成年人物或新的服装品牌。

### 点点：观察与提示

- 白色云朵轮廓头部；深蓝色电子屏脸、青蓝眼睛与微笑。
- 紫色球形天线、白蓝身体、默认爱心胸屏、短小手臂与底部蓝色悬浮投影。
- 表达默认、提示、鼓励三种状态。提示姿态可以伸手，但不能改变头部轮廓、胸屏形状或机械结构。
- 不与长方头、牙齿胸标、轮式底座的刷牙机器人混淆；不复用当前同名兔子资源 ID。
- 在网站中先承担预设教学提示，不暗示具备尚未实现的实时 AI 理解能力。

### 辅助角色与旧资源

刷牙机器人与 RGB 小精灵属于可扩展角色，不是第一批必须接入的网站主角。只有在现有关卡确需该类对象且不改变学习目标时才制作。旧熊猫、兔子、栗奇及其他现有资源继续支持旧作品和自由创作，归入清楚标注的经典资源组。

## 3 视觉语言与功能边界

插画采用儿童水彩绘本：暖光、轻微纸纹、清透而明快的颜色、柔和阴影和明确轮廓。避免照片、塑料 3D 玩具感、深暗恐怖气氛、粗重颗粒、模糊脸部和过度繁杂背景。新的教学页面内不混用同一角色的水彩版与立体玩具版。

建议界面色板（设计建议，不是从图片测量所得）：暖奶白 `#FDFBF7`、白卡片 `#FFFFFF`、深蓝灰正文 `#25364A`，点缀使用暖橙、天空蓝、薄荷绿和淡紫。具体色值在组件中统一登记并检测对比度。不能把浅色点缀当作正文色；不能把舞台网格和路线画得像背景装饰而失去辨认度。

| 可以生成 / 派生为位图                | 必须由代码控制                                   |
| ------------------------------------ | ------------------------------------------------ |
| 角色立绘、头像、表情、非精确装饰道具 | 所有文字、数值、工具提示、按钮标签               |
| 无人物、无文字的场景底图             | 网格、格坐标、路径、障碍占位、起点终点           |
| 首页故事插画、课程封面               | 图表轴线、条形高度、数量、分类槽位、答案状态     |
| 庆祝插图与少量外围装饰               | 实际积木、类别颜色、执行高亮、输入框、可访问状态 |

操作区域保留现代清晰控件：容器约 20–24px 圆角、按钮 pill 或 16px 圆角，按压态不导致布局跳动。统一功能图标的线宽与视觉大小；插画用于叙事，不把每个操作按钮都变成一张复杂图片。

## 5 输出、命名与几何规范

| 类型               | 母版建议                    | 网页交付                                                | 首轮文件体积目标 |
| ------------------ | --------------------------- | ------------------------------------------------------- | ---------------- |
| 透明舞台角色、道具 | 1024×1024 PNG，真实 Alpha   | 512×512 透明 PNG，或经现有加载与导出链路验证的透明 WebP | 每张不超过 150KB |
| UI 半身像          | 1024×1024 透明 PNG          | 256×256；展示 44–64 CSS px 时检查脸部                   | 每张不超过 80KB  |
| 4:3 舞台背景       | 1440×1080 或更高的 4:3 原图 | 960×720 WebP 或 PNG                                     | 每张不超过 300KB |
| 首页故事图         | 1600×900 或更高             | 依据布局响应式缩放，不裁关键角色                        | 不超过 450KB     |
| 单元封面           | 1024×1024                   | 512×512，统一安全区                                     | 每张不超过 120KB |

这些是待测试的预算，不是现有图片实测值。若合格画质无法达到目标，记录实际体积与首屏代价后调整，不能用模糊脸部换取通过。母版不进入首页首屏下载路径；课程封面按需加载，不为一张页面预加载全部姿态。

命名示例：`assets/characters/story-ip/tuantuan-stage-front-v1.png`、`assets/ui/story-ip/diandian-hint-v1.png`、`assets/backgrounds/story-ip/garden-v1.webp`。实际 ID 在注册时记录；同一 ID 不改变角色身份，已发行文件不原地覆盖。`参考资料` 作为设计来源，不整目录复制到公开站点。

透明图主体四周保留约 8%–12% 安全留白，边缘不能有白色纸底、黑边或棋盘格假透明。人物不能把脚、天线、手臂裁掉；同一组姿态必须统一可见尺度及基准点。最终锚点、显示倍率、碰撞形状和尺寸存入项目现有的素材几何配置，不散落在 JSX 常数中。

游戏几何沿用 480×360 / 大格 40 / 12×9。逻辑坐标和可见主体中心对齐格心；脚底、悬浮投影作为美术测量参考，渲染锚点根据实际透明边界校准，避免人物身体跨到上一格。天线、背包、辉光、阴影不计入碰撞范围。旋转、转向和造型切换不使逻辑格心漂移。旧造型的锚点不随本次新图校准而改变。

参考图虽有立体透视，交互舞台必须服务于正交网格。背景不能出现与代码路网不一致的“可走道路”、假的终点、假的金币或角色。视线要能区分真实可交互目标与外围装饰。

## 6 后续生成 / 编辑模板

本节是后续制作模板；已经使用的完整提示词逐项登记在首批素材台账。制作时同时提供实际参考图，不只复制角色名字。若针对已有图去背景、改姿态或编辑，按当时可用的图片编辑工具与技能执行；不要用无参考的新生成结果替代原 IP。

### 通用风格前缀

> 严格延续所附原角色板的身份、脸型、服装、头身比例与关键颜色。儿童水彩绘本插画，暖光，清透明亮，细微纸张笔触，轮廓在缩小后依然清楚。用于儿童编程网站，不是新角色设计。不要照片感、塑料 3D、阴暗气氛、文字、水印、UI 面板或多余人物。

### 舞台团团

> 使用团团原角色板作为形象约束，制作单个全身的【正面 / 朝右】站姿。橙色长袖、蓝色背带裤、棕色背包与鞋，保持原发型与脸部。真实透明背景，完整脚底与头部，四周安全留白，清晰简洁轮廓。以脚底中点作为落点参考，不画地面场景，不画碰撞圈、格子、文字或人物设定板。

### 点点提示像

> 使用点点原角色板。白色云朵头、深蓝屏幕脸、青蓝眼睛、紫色球形天线、白蓝身体、爱心胸屏；单个角色做【默认 / 指向提示 / 温和鼓励】动作。真实透明底，小尺寸可辨，不能改成长方头轮式机器人，不换成星形胸屏，不加对话文字。

### 空舞台背景

> 参考所附关键帧的水彩笔触与暖光，制作 4:3【花园 / 云岛外围 / 数据工坊】空背景。中央主要活动区域明亮、平整、低细节，装饰集中在边缘。无角色、无文字、无图表、无网格、无道路和目标标记，不画假宝箱或金币。网格、路线、障碍和互动对象会由程序后加。

### 首页组合图

> 同时以团团和点点两张角色板为约束，表现团团正在探索、点点陪伴观察的绘本场景。双主角身份保持一致，画面明亮有留白，标题和按钮由网页生成。无文字、无完整网页截图、无陌生主角，不用大量小装饰遮盖角色表情。

制作记录必须将方括号替换为该资产的确切姿态或场景，附具体参考文件。仅有提示词不是验收证据，最终图片必须回看角色板并放进真实页面。

## 7 素材登记与验收模板

与 [现有素材溯源](asset-provenance.md) 保持一致，必要时扩充登记字段，但不伪造已有 schema 支持尚未实现的字段。

```text
AS 编号 / 资源 ID / 相对交付路径：
角色与用途 / 对应页面和 taskId / 课程版本：
来源类型：用户既有设计 / 基于参考的生成或编辑 / 其他真实来源
参考源文件 / 母版位置：
如有生成：工具、日期、完整提示词、参考图、后续编辑记录
像素尺寸 / 字节数 / Alpha 检查：
显示倍率 / 渲染锚点 / 碰撞形状与参数（舞台资源必填）：
身份一致性 / 真实尺寸截图 / 检查结论：
内部试用审查状态 / 发行审查状态 / 替代或下架办法：
旧资源保留情况 / 新旧版本与导入导出验证：
```

逐张验收：

- [ ] 是角色板中的同一角色，未出现性别、服装、脸型、胸屏或机械结构漂移。
- [ ] 用真实 Alpha 而非棋盘格图片；没有纸底矩形、裁肢、多余手指或破碎边缘。
- [ ] 480×360 舞台与小头像尺寸可识别；背景不会淹没角色、格线和目标。
- [ ] 图片不含任务文字、错误数字、伪路径、伪目标或固定答案。
- [ ] 新 ID、路径与来源齐全；旧文件未被覆盖；用户旧项目仍可解析。
- [ ] 游戏资源已登记渲染与碰撞几何；与原参考程序结果一致。
- [ ] 新图在页面中的显示、缓存、加载失败和项目包恢复均经过验证。

只有图片检查、页面检查、运行检查都通过，才能从“待接入”改为“已验收”。支持角色未被实际课程使用时，不因存在形象板就计为网站已完成功能。
