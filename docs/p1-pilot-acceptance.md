## 参数与几何约束

- 移动为格；X/Y 为从 0 开始的列/行，大格 12×9 时范围分别为 0–11、0–8。旧细格继续使用对应范围。
- 旋转 1–360 度、等待/说话 0.1–10 秒、重复 2–10 次、大小变化 -80–80、得分变化 -1000–1000；限制与编译器一致。
- 网格下拉中的非预设合法数字以标准数值影子积木保存，重新加载不会丢值。确认参数同步提交快照，不依赖延后事件；相同快照不产生额外撤销项。
- 工作区“修改参数”提供至少 44px 的列表入口，支持键盘选择并打开数值/文字/对象编辑器；无需精确点中积木上的小数字。关闭对话框后归还工作区焦点，不遗留拖拽状态。
- 运行证据对应实际执行的程序。新版代码被改动时停止旧运行，不能把“运行后再重排”的程序算作已运行。
- 新角色可见主体约 36 逻辑像素，格心与可见主体中心对齐；碰撞体不由光晕、背包或天线扩大。旧造型几何不改。
- 实体宝箱接触边缘后阻挡；路线终点要求实际格心；金币可穿过但跨格移动仍观察接触。三种概念不混为同一判定。
- 单步测试必须记录真实暂停及循环体执行次数，不能仅把两次连续运行的位置相等称作单步一致。

比较工作台读取程序中的变量引用、字面比较数值与本次运行报告。未配置比较或复杂表达式瞬时值未被记录时，明确不画推测柱高；正负数使用共同零线、数字和标签。路线小图由当前地图生成，分段是观察示意，圆点才是实际轨迹。

## 证据与复验

1. `pnpm check`：格式、静态检查、类型、单元测试、生产构建。
2. `pnpm course:baseline`：64 行 v3 基线与 11 份冻结实现。
3. `pnpm exec playwright test e2e/pilot-acceptance.spec.ts --project=desktop-1366`：八关共 32 条运行记录。
4. `pnpm exec playwright test e2e/geometry-acceptance.spec.ts e2e/teaching-interactions.spec.ts`：三个视口的实际几何、参数与教学交互。
5. `pnpm test:pilot:summary`：校验八份记录与三个几何文件，写出 `artifacts/pilot-acceptance/summary.json`。
6. `pnpm build` 后 `pnpm test:offline:story`：独立生产服务断网重载及运行第一关。缓存版本 `kids-code-shell-v5-teaching`，包含新导师和完成插图。

输出位置：`artifacts/pilot-acceptance/<taskId>-<viewport>.json`、对应 PNG、`geometry-<viewport>.json`。每个几何文件应有 33 项通过，包含新旧版本各一项 `single-step-really-pauses`。屏幕为 1366×768、1024×768 Chromium 与 1194×834 横屏 WebKit；图形测试与完整压缩包回归顺序执行，避免资源争用导致虚假超时。

开发验收桥接模块 `pilot-store.ts` 只用于共享页面实际的 Vite 状态单例，避免 HMR 时间戳造成第二份测试状态；不提供生产 API。
